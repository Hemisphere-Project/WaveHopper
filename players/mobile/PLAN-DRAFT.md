## Why not a plain wrapper

The PWA plays through a `<video>` element with hls.js. Inside a store app:

- **iOS** suspends WebView JavaScript when locked/backgrounded → hls.js stops
  fetching (The Lot dies when its buffer runs out), and retry/auto-skip,
  now-playing polling and lock-screen next/prev all stop.
- **Android** needs a foreground service with a media notification
  (`foregroundServiceType="mediaPlayback"`, Android 14+) or the OS kills
  playback; Bluetooth buttons and Android Auto only talk to a native
  MediaSession.

So playback is **native**; the web UI becomes a remote control.

## Architecture

- **Native engine** (Capacitor plugin, working name `WaverzAudio`):
  Android = Media3/ExoPlayer in a `MediaSessionService` (later
  `MediaLibraryService` for Android Auto); iOS = AVPlayer + `AVAudioSession`
  (playback) + Now Playing / remote commands (later CarPlay templates).
  It owns: the station queue, connect → retry once → skip (same supervisor
  policy as the M5 and the web app), network-change recovery, lock-screen
  metadata, now-playing polling while playing (`/api/now-playing.php`, 30 s),
  ICY titles.
- **Web UI** (`players/web/public`, bundled in the app — NOT loaded live from
  waverz.net): visuals, skins, config mode, station choice. Sends
  `setQueue(stations)`, `play(id)`, `next/prev`, `stop`, `setVolume`; receives
  state / buffering / title events. `app.js` feature-detects the plugin and
  keeps the `<video>`/hls.js path for the browser — one UI codebase.
- **Content stays remote**: catalog, icons, metadata from waverz.net, so
  stations can be added without a store release.
- Build step in `players/mobile/`: copy `players/web/public` into the app's
  webDir without `api/`, `content/`, `stats/` and the service worker.

## Rights-gated catalog (the risk reducer)

Risk inventory done 2026-09-27:

| Item | Risk | Handling |
|---|---|---|
| Station logos (official trademarks; NTS's reused on 17 channels) | High | Never bundled; shown only where `logo: granted`, fetched at runtime; else a generated tile (name on station color) |
| Stream URLs — several dug out of site internals (LYL private GraphQL, Wave Zero `config.js`, NTS relay UUIDs, Kiosk bundle) | Medium | Ask each station for its official stream URL; app pack uses only those |
| Now-playing: mostly undocumented public APIs; LYL private GraphQL; **The Lot scraped from HTML** | Medium | Shown only where `metadata: granted` |
| Station / channel names, colors | Low | Nominative use, only for agreed stations; never in store listing |
| Recording / downloading | — | Never add (guideline 5.2.3 targets it); no timeshift, no audio caching |
| Fonts VT323 + Fredoka (OFL), hls.js (Apache-2.0) | Low | Ship license texts in an About/Licenses screen |
| Telemetry (anonymous install id, coarse IP location) | Low | Honest privacy label + Play data-safety form + `waverz.net/privacy` |

Design:

1. **`rights` block in the source** `content/stations/<id>.json` (source-only,
   like `m5Url`; absent = not granted):
   ```json
   "rights": { "app": "granted", "logo": "granted", "metadata": "granted",
               "agreed": "2026-10-14", "ref": "who / which thread" }
   ```
2. **App pack** generated by `tools/build.py` at a new path
   (`/content/app/stations.json`): only `app: granted` stations; `icon` only
   with `logo`; `nowPlaying` only with `metadata`; official stream URL.
   Additive path → safe under CONTENT-API.md's append-only rule (document it
   there first).
3. **Logo-free binary**; store screenshots use generated tiles.
4. M5 pack and PWA unchanged for now; consider the same `logo` gate for the
   PWA once the campaign has results.

## Outreach ask (maps 1:1 onto `rights`)

Per station, separable yeses: (a) link your public stream in the app →
`app`; (b) show your name + logo → `logo`; (c) show your now-playing info →
`metadata`; (d) which stream URL should we use? Offer back: anonymous
listener counts from telemetry, a link to their site on every play, no ads.
Record answers in `content/stations/<id>.md` (evidence) + the `rights` block.

## Other implications to handle

- **Contract additions** (CONTENT-API.md): telemetry player types `ios` /
  `android`; optional low-bitrate `mobileUrl` for cellular (NTS 256 kbps ≈
  115 MB/h); the app pack path.
- **Transport**: iOS ATS `NSAllowsArbitraryLoadsForMedia` and Android
  cleartext allowlist only if any official stream is plain HTTP.
- **The Lot HLS**: the web app forces hls.js for Livepeer even where native
  HLS exists — validate AVPlayer on it first thing in phase 2 (ExoPlayer is
  expected to be fine).
- **Accounts**: Apple $99/yr (org → D-U-N-S); Google Play $25 once. An
  **organisation** Play account avoids the personal-account rule (closed test
  with 12 testers × 14 days before production).
- **Server load**: app installs multiply now-playing requests; the server-side
  fetcher cache absorbs it — check Infomaniak limits before launch.
